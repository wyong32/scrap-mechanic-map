# 默认地表世界官方正俯视高清地块设计

日期：2026-07-31  
状态：设计已由用户逐项确认，等待文档复核

## 1. 背景

当前默认地表地图混合使用了两类图片：

- 原仓库已有的真实俯视地块；
- 从 Scrap Mechanic 1.0 官方资源提取并校正的等距缩略图。

第二类图片的原始有效分辨率较低，而且部分大型地点只使用一张
`256 × 256` 图片覆盖多个地图格。地图放大后会出现模糊、斜向拉伸、
错误旋转、黑块、海面岛屿碎片和跨格接缝不连续等问题。

本设计使用安装目录中的官方 TileEditor 重新渲染默认 DB 实际使用的
异常地块，建立统一、真实、可复用的正俯视高清底图。

## 2. 目标

首批交付需要：

1. 读取随站点提供的默认 DB，找出地表世界实际使用的唯一地块。
2. 只重建当前依赖模糊等距缩略图的异常地块，保留已经正常的真实俯视图。
3. 使用官方 TileEditor 生成正俯视、北向上、统一光照的母版。
4. 母版采用每个地图格 `256 × 256` 像素的固定密度。
5. 在构建阶段生成适合现有地图渲染器使用的切片和元数据。
6. 页面刷新后自动载入默认 DB 和新底图，不要求用户手动上传。
7. 保留现有搜索、筛选、区域切换和图层交互。
8. 地点名称、POI 图标和资源标记独立于真实底图，默认不显示。

## 3. 非目标

首批不包含：

- 一次性重建官方资源中的全部地块；
- 重建所有固定区域和所有玩家存档的专属地图；
- 自行实现完整的游戏模型、材质、灯光和着色器渲染器；
- 使用相似图片、手绘参考图或随机素材填补失败地块；
- 改变玩家上传存档的现有入口和基础交互结构。

首批流程稳定后，可以用相同管线扩展到其他固定区域和玩家上传存档。

## 4. 方案选择

采用“官方 TileEditor 批量渲染”方案。

未采用的方案：

- WorldBuilder 整图截图：接缝少，但输出巨大、难更新，单个地块不能复用。
- 自建离线渲染器：自动化潜力高，但需要复刻游戏渲染效果，工程量和失真风险最高。

TileEditor 方案能够直接使用官方地块、模型、材质和纹理，同时保留按
UUID 缓存与复用的能力。

## 5. 数据流

```text
默认 DB
  -> 解析地表地块实例
  -> 按 UUID 去重
  -> 与现有高清资源及官方图集清单比对
  -> 生成待渲染清单
  -> TileEditor 标准化捕获
  -> 捕获校验
  -> 按地图格无损切片
  -> 生成清单与图集
  -> 默认地图自动加载
  -> 浏览器视觉与交互验收
```

### 5.1 输入

- 站点随附的默认存档 DB；
- Scrap Mechanic 1.0 安装目录中的 `.tile` 文件及其依赖；
- 当前旧版真实俯视地块；
- 当前官方图集清单，用于识别等距缩略图来源；
- 存档中的地块坐标、占格范围和旋转信息。

### 5.2 待渲染清单

清单以唯一地块 UUID 为单位，至少记录：

- UUID；
- 官方 `.tile` 源文件；
- 宽度与高度（地图格）；
- 期望母版像素尺寸；
- 默认存档中的使用次数；
- 使用到的旋转值；
- 现有资源类型；
- 捕获与校验状态。

清单必须由默认 DB 和资源索引确定性生成，不能依赖人工选择图片。

### 5.3 输出

每个地块产生：

- 一张标准方向的完整高清母版；
- 一组 `256 × 256` 无损切片；
- 一条包含 UUID、占格尺寸、像素密度、原点和版本的元数据记录；
- 捕获校验结果；
- 用于追踪来源与重新生成的日志。

生成资源应放在明确的派生资源目录中，不能覆盖官方安装文件。

## 6. TileEditor 捕获规范

每个唯一地块只捕获一次标准方向母版。

固定规范如下：

- 相机：严格正交俯视；
- 方向：北向上；
- 投影：正交投影，禁止透视；
- 密度：每地图格 256 像素；
- 构图：完整覆盖地块边界，不裁掉边缘内容；
- 光照：固定时间、曝光、阴影和环境设置；
- 背景：使用能够区分透明区域和真实深色场景的固定捕获背景；
- 后处理：禁止自动锐化、模糊、拉伸和非整数缩放；
- 格式：无损 PNG。

母版尺寸由地块占格决定：

| 地块尺寸 | 母版尺寸 |
| --- | --- |
| 1 × 1 | 256 × 256 |
| 4 × 4 | 1024 × 1024 |
| 8 × 8 | 2048 × 2048 |
| 16 × 16 | 4096 × 4096 |

其他尺寸同样按 `地图格数 × 256` 计算，不允许先生成小图后放大。

真实底图保留官方场景中从正上方可见的地形、道路、水体、建筑、植被、
道具和结构。名称、POI 图标、资源点和任务提示不烘焙进底图。

## 7. 拼接与旋转

捕获结果始终保持标准方向。地图运行时根据存档应用旋转和坐标变换。

规则如下：

1. 仅允许 `0°`、`90°`、`180°`、`270°` 四种正交旋转。
2. 禁止通过镜像代替旋转。
3. 大型地块的母版按统一原点切片，不能把一张缩略图复制到每个格。
4. 每张切片与母版保持一一对应的整数像素边界。
5. 相邻切片必须能恢复为与母版像素一致的完整图片。
6. 海洋、湖泊和空白区域必须来自真实地块捕获，不得使用相似岛屿碎片填充。

如果现有渲染器使用整张跨格图片，则构建产物可以同时保留母版；如果使用
单格图集，则使用无损切片。两种输出必须共享同一份坐标和旋转元数据。

## 8. 图层与现有交互

真实场景内容属于基础地形层，默认显示。

以下内容保持为独立覆盖层：

- 地点名称；
- POI；
- 资源；
- 任务；
- 危险或首领提示；
- 进度数据。

地点名称、POI 和资源默认关闭，用户勾选后显示。是否显示覆盖层不影响底图
真实性，也不改变存档解析结果。

现有区域切换、名称搜索、分类筛选、地点列表、缩放、拖拽和 URL 状态继续保留。

## 9. 默认 DB 与玩家存档

页面启动时：

1. 优先自动加载站点随附的默认 DB；
2. 使用该 DB 的地表布局和已生成的高清资源展示默认真实地图；
3. 用户上传自己的 DB 后，使用玩家存档替换当前布局与进度；
4. 玩家存档引用到已经生成的 UUID 时，直接复用高清地块；
5. 玩家存档引用到首批清单之外的异常地块时，明确标记资源尚未生成，
   不用错误图片伪装成功。

固定区域后续也使用官方资源和同一捕获规范生成，临时参考图不作为最终底图。

## 10. 失败处理

捕获或构建出现以下任一情况时，该资源不得进入默认发布：

- 找不到 `.tile` 源文件或依赖；
- TileEditor 未成功加载地块；
- 输出尺寸不符合占格尺寸；
- 相机不是正俯视或方向无法验证；
- 图片为纯黑、近似纯色或透明度异常；
- 图片与已知占位图或其他 UUID 输出异常重复；
- 切片缺失或数量错误；
- 切片重组后与母版不一致；
- 旋转测试失败；
- 道路、水岸或结构在切片边界发生程序性错位。

失败报告必须给出 UUID、源路径、处理阶段和明确原因。构建不能静默退回到
模糊等距缩略图。

旧资源在新资源全部通过首批验收前可以继续保留在磁盘中，但不能被错误标记为
已经高清修复。

## 11. 自动校验

构建阶段至少执行：

- 清单可重复生成测试；
- UUID 与源文件映射测试；
- 占格尺寸和像素尺寸测试；
- 切片数量与命名测试；
- 母版切片后重组的像素一致性测试；
- 四方向旋转与坐标变换测试；
- 纯黑、近似纯色、异常透明图片检测；
- 重复图片和已知占位图检测；
- 所有清单项均有明确成功或失败状态的完整性测试。

视觉算法只能用于发现可疑结果，不能擅自用其他图片替换失败输出。

## 12. 浏览器验收

使用默认 DB 在本地预览中完成：

1. 刷新页面后无需上传即可看到默认真实地图。
2. 在总览缩放检查整张地图，没有大面积黑块和随机岛屿碎片。
3. 在正常缩放检查道路、水岸和大型地点的位置与方向。
4. 在最大缩放检查图片没有二次拉伸和明显像素不足。
5. 检查大型地块跨格连续，没有重复缩略图或接缝错位。
6. 检查四种旋转的代表地块，没有倒立和镜像。
7. 检查地点名称、POI、资源默认关闭，勾选后正常显示。
8. 检查搜索、筛选、地点列表、区域切换和 URL 状态没有回归。

## 13. 分阶段交付

### 阶段 A：能力门禁

- 验证官方 TileEditor 可以稳定打开指定 `.tile`；
- 完成一个代表性大型异常地块的标准捕获；
- 验证尺寸、方向、切片和浏览器显示。

如果能力门禁失败，先解决 TileEditor 启动或捕获问题，不进入批量生产。

### 阶段 B：默认地表首批

- 生成默认 DB 使用的异常 UUID 清单；
- 批量捕获并校验；
- 构建高清资源；
- 集成默认加载；
- 完成自动和浏览器验收。

### 阶段 C：后续扩展

- 其他固定区域；
- 默认 DB 未使用但玩家存档常见的地块；
- 玩家上传后按需提示或离线生成缺失地块；
- 在不降低真实性的前提下优化图集体积和加载速度。

## 14. 完成定义

首批工作只有在以下条件全部满足时才算完成：

- 默认 DB 地表世界实际使用的异常地块均有通过校验的官方高清母版；
- 地图默认自动加载；
- 不再使用模糊等距缩略图作为这些地块的底图；
- 不存在已知黑块、随机海岛碎片、倒立、镜像和跨格错位；
- 覆盖层默认状态与现有交互符合设计；
- 自动测试和浏览器三级缩放验收全部通过；
- 失败清单为空，或失败项明确阻止交付而不是被占位图掩盖。
