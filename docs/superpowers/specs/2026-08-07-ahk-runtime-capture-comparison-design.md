# AHK 游戏内取图对比实验设计

## 目标

在同一个 Scrap Mechanic 1.0 地点上，比较三种真实地图图片来源：

1. `sm_overview` 已有的开源预制地块 JPG；
2. 官方 TileEditor 正俯视取图；
3. `sm_overview_ahk` 的游戏内高空取图方法。

实验既评估最终画质，也评估补齐 1.0 缺失地块时的生产效率。实验不直接替换网站底图；只有对比结论明确后，才单独决定是否批量采用。

## 样本

选择默认地表世界中一个同时包含道路、海岸和植被的区域。该区域必须能够对应到一个已有开源图片的普通地块，使三种来源都能展示相同内容。

三张图统一为北向上，使用相同的世界范围、相同的最终像素尺寸和不含界面的有效画面。不得通过修补、生成式补全、锐化或内容感知处理掩盖来源差异。

## AHK 路线

AHK 样本复现原 `sm_overview_ahk/makemap.ahk` 的关键方法：

- 启动官方 Scrap Mechanic 游戏；
- 载入默认对比存档；
- 使用 `/tp x,y,250` 传送到目标上空；
- 使用原流程要求的 FOV 90；
- 等待至少 4 秒，让目标区域完成流式加载；
- 使用 Alt+Z 隐藏界面；
- 截取游戏窗口中央 750×750 像素；
- 仅进行方向校正和与另外两张图相同范围的裁切。

若当前 1.0 游戏不再支持原 `/tp` 行为，可以使用项目中已经审查过的 `/smoverview_capture x y 250` 相机补丁，但必须在结果中明确标注为“原方法的 1.0 兼容实现”，不能声称它是未经修改的原 AHK 脚本。

## 对比成品

输出一张三栏 PNG：

- A：开源预制地块图；
- B：TileEditor 正俯视图；
- C：游戏内高空截图。

每栏标注来源、原始分辨率、最终裁切分辨率、方向处理和一次成功取图耗时。另保存未缩放的原始样本，保证可以检查纹理、树冠、道路边缘和海岸接缝。

## 画质指标

- 视角是否严格接近正俯视；
- 地物方向和比例是否与开源图一致；
- 道路与海岸能否在相邻地块继续衔接；
- 树冠、建筑和阴影是否在边界被硬裁切；
- 纹理是否清晰，是否存在拉伸、模糊、黑块或加载占位；
- 光照和天气是否造成无法复用的视觉差异。

## 效率指标

对每种可重复取图方法记录：

- 冷启动准备时间；
- 定位和设置相机时间；
- 地形等待时间；
- 截图、裁切和校正时间；
- 单张成功总耗时；
- 失败原因、重试次数和重试耗时；
- 每张需要的人工操作次数。

根据实测结果分别估算：

- 制作 173 个缺失唯一 Tile 母版的总耗时；
- 若按世界坐标逐格截图，覆盖默认世界所需的总耗时；
- 可自动化比例、磁盘占用和运行期间是否需要人工值守。

效率估算必须区分“每种 Tile 只做一次并旋转复用”和“按整张世界逐坐标截图”两种生产模式，不能把两者混为同一工作量。

## 验收门槛

- 三张图确实来自同一世界范围；
- AHK/游戏内样本没有 HUD、聊天框、光标或未加载黑块；
- 原始样本和三栏成品均可在本地打开；
- 报告包含真实计时，不使用脚本设定值冒充实测值；
- 明确说明哪种方法画质最好、哪种最快，以及其是否适合补齐 173 个唯一 Tile；
- 单个能力样本失败时停止，不批量运行或覆盖当前网站底图。
